# 986 argument redefined by a local in the same scope

Severity: low · Confidence: medium · CWE: none

Opt-in: reported under `--category lint` or `--enable 98`.

## What it means

A named function argument is shadowed by a `local` of the same name declared in
the function body's own scope, so the argument is dead from that point on.
luacheck reports this as code 412.

`function f(a) local a = 1 end` is one finding: the `local a` in the body scope
redefines the argument `a`. The argument's value is unrecoverable once the local
is declared, which is almost always a mistake — the argument is either unused or
was meant to be mutated, not rebound.

A `local` of the same name inside a **nested** block (`do local a = 1 end`) is
not flagged: the `do` block is a different scope, and the outer local is only
shadowed inside that block.

`...` and `self` are not named arguments and are never reported.

## Example

```lua
local function f(a)
  local a = 1  -- 986: a was an argument of this function
  return a
end
```

The negative case — a `do` block is a separate scope:

```lua
local function f(a)
  do local a = 1 end  -- not reported: a is in a nested scope
  return a
end
```

## How to fix

Rename the local, or remove the redundant `local` if the argument was meant to
be reassigned directly:

```lua
local function f(a)
  a = a + 1  -- reassign the argument, no new local
  return a
end
```
