# 951 accessing an undefined variable

Severity: low · Confidence: medium · CWE: none

Opt-in: reported under `--category lint` or `--enable 95`.

## What it means

The code reads a global that neither the Lua standard in use nor a loaded platform profile defines: most likely a typo (`pritn("x")`). luacheck reports this as 113 and selene as `undefined_variable`. Like luacheck's default, a global the file assigns itself is still undefined where it is read; assigning it is a separate finding (952). With `--allow-defined` (selene's rule, luacheck's `allow_defined`) a global the file assigns anywhere, before or after the read, is defined, and the assignment is not reported either. When a built-in standard defines the name, the message says which (`defined by --std +luci`).

The standard is the one `--std` names (`lua51`, `lua52`, `lua53`, `lua54`, `luajit`), or the union of all of them when it names none. A platform profile (`--std +luci`) defines every name its patterns start with, and may list more with `globals`. A platform can provide names none of these list, which is why the finding is low and medium confidence.

## Example

```lua
local greeting = pritn("hello")
```

## How to fix

Correct the name, add `local` to the definition, or declare the name the platform provides in a profile (`globals` in a `--rules` file).

## Fix prompt

```prompt

```
