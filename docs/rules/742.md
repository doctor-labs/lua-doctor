# 742 matches a declared pattern rule

Severity: medium · Confidence: high · CWE: set by the declaration

## What it means

A `pattern_rules` entry in a `--rules` file matched an expression in the analyzed file. The pattern is one Lua expression with metavariables: `$NAME` matches any one expression, and a name used twice must match the same expression both times. The finding is named after the rule's `id`, and its severity and CWE come from the rule.

## Example

From `test/fixtures/pattern_rules/vendor_rules.lua`, asserted in `test/spec/pattern_rules_spec.lua`:

```text
return {
   name = "pattern-fixture",
   pattern_rules = {
      {id = "vendor-run", pattern = "vendor.run($CMD)", severity = "high", confidence = "high", cwe = "CWE-78"},
   },
}
```

This is a rules file, not a program: it fires only when loaded with `--rules`, so it is not run as a lua example.

With that declaration, `vendor.run("ls")` and `vendor.run(cgi.x)` each fire a 742 named `vendor-run`, and `vendor.other("ls")` does not.

## How to fix

Read the rule's `id` and the matched line. If the call is a real problem for your code, change it as the rule's documentation says. If the rule is wrong for this code, narrow the pattern or remove the rule from the `--rules` file.

## Fix prompt

