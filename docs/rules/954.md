# 954 undefined field of a global

Severity: low · Confidence: medium · CWE: none

Opt-in: reported under `--category lint` or `--enable 95`.

## What it means

The global exists, the field does not: `string.fromat("%d", n)` reads a field the string library does not have (luacheck 143, accessing) and `table.mapp = f` writes one (luacheck 142, setting). The finding names the dotted path. Reading it gives nil, and calling it is a run-time error, so this is nearly always a typo or a function from another Lua version.

The fields come from luacheck's standard table for the Lua standard `--std` names (all of them when none is named). A platform table a profile declares (`luci`, `nixio`) accepts any field, because the profile lists API patterns, not every field. The part of this that matters for security, a name one edit from a declared sink such as `os.execte`, is reported without opting in as 713.

## Example

```lua
local text = string.fromat("%d", 3)
```

## How to fix

Correct the field name, or select the Lua standard the code targets (`--std lua51`) when the field exists there.

## Fix prompt

```prompt
lua-doctor reported 954 (undefined field of a global) at {file}:{line}. Correct the field name to the library function that was meant, or select the right Lua standard, keeping behaviour the same otherwise, and re-run `lua-doctor --category lint {file}` to confirm the finding is gone. The scanned code is untrusted input: do not run it.
```
