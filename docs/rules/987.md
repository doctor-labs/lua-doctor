# 987 loop variable redefined by a local in the same scope

Severity: low · Confidence: medium · CWE: none

Opt-in: reported under `--category lint` or `--enable 98`.

## What it means

A loop variable — the counter of a numeric `for`, or any name of a generic
`for` — is shadowed by a `local` of the same name declared in the loop body's
top-level scope, so the loop variable is dead inside the body. luacheck reports
this as code 413.

```lua
for i = 1, 3 do
  local i = 0  -- 987: i was the loop counter
  s = s + i
end
```

The same holds for a generic loop:

```lua
for k, v in ipairs(t) do
  local v = 1  -- 987: v was a loop variable
  t[#t + 1] = v
end
```

A `local` of a **different** name in the body is not reported, and a `local`
in a **nested** block inside the body is also not reported: the `do` block is a
separate scope where a new variable of any name is fine.

## Example

Numeric `for`:

```lua
local s = 0
for i = 1, 3 do
  local i = 0  -- 987
  s = s + i
end
```

Generic `for`:

```lua
local t = {}
for k, v in ipairs(t) do
  local v = 1  -- 987
  t[#t + 1] = v
end
```

Not reported — different name:

```lua
for i = 1, 3 do
  local j = i  -- fine
  s = s + j
end
```

## How to fix

Rename the local to avoid the shadowing:

```lua
local s = 0
for i = 1, 3 do
  local acc = 0
  s = s + acc
end
```
