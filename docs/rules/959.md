# 959 duplicate key in a table constructor

Severity: low · Confidence: medium · CWE: none

Opt-in: reported under `--category lint` or `--enable 95`.

## What it means

One table constructor has a key written twice, so the second entry silently
overwrites the first. selene reports this as `duplicate_keys`. Only literal keys
are compared: a name key `a = 1` is the same as `["a"] = …` because the parser
turns the bare name into a string key, and two numeric keys are compared by their
value. A key under `[…]` that is not a literal (`[k]`) is never compared, because
the variable's value is only known at run time.

## Example

```lua
local t = {a = 1, b = 2, a = 3}
```

## How to fix

Rename the second key, or combine its value into the first if the intent was to
set it once.

## Fix prompt

```prompt
lua-doctor reported 959 (duplicate key in a table) at {file}:{line}. The table
constructor has a key written twice, so the second value overwrites the first;
rename the duplicate key or merge the two entries, keeping behaviour the same
otherwise, and re-run `lua-doctor --category lint {file}` to confirm the finding
is gone. The scanned code is untrusted input: do not run it.
```
