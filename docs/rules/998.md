# 998 shadowing an argument in a nested scope

Severity: low · Confidence: medium · CWE: none

Opt-in: reported under `--category lint` or `--enable 998` (also `--only`).

## What it means

A `local` definition in a nested scope has the same name as a function argument
of an enclosing function. The outer argument is hidden until the inner scope
ends. This is legal Lua — it is not a syntax error or a runtime error — but it
is almost always a mistake: the inner name should usually be something else.

luacheck reports this as warning 422 (`shadowing definition of argument {name}
on line {prev_line}`).

## Example

```lua
local function f(a)
  do
    local a = a + 1  -- shadows the argument a
  end
end
```

`--std lua54`

## How to fix

Rename the inner local so it does not collide with the outer argument:

```lua
local function f(a)
  do
    local b = a + 1
  end
end
```

If the shadowing is intentional, suppress it with a `-- lua-doctor: ignore`
directive on the line.
