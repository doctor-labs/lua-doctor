# 713 call to an undefined name that looks like an execution sink

Severity: medium · Confidence: medium · CWE: none

## What it means

A call names something that does not exist in the configured Lua standard or in any loaded platform profile, and the name is one typo away from an execution API lua-doctor models (`os.execte` for `os.execute`, `loadstrng` for `loadstring`). At run time the call is a call of nil and fails, so the code does not do what its author meant. For this tool it is worse than a failure: no declared sink matches the misspelled name, so a finding the real API would have produced (701, 709, 710) is silently missing.

Both halves are required. `io.open` is one edit from `io.popen`, but it is a real function and is not reported. A name the file assigns itself (`function loadstrinx() end`) is defined and is not reported either, and a table that a profile leaves open (`luci.sys.whatever`) is not guessed at.

Only one edit (a missing, extra, wrong or swapped letter) counts as a typo: two edits would make `readfile` a misspelling of `loadfile`, and `readfile` is a helper firmware trees define for themselves.

## Example

```lua
local cmd = luci.http.formvalue("cmd")
os.execte(cmd)
```

## How to fix

Correct the spelling. Once the name is the real API the taint engine sees the call and reports the flow it carries. If the name is a genuine function defined elsewhere (a global from another file), declare it in a profile with `globals`, or suppress the finding with `-- lua-doctor: ignore 713` on that line.

## Fix prompt

```prompt
lua-doctor reported 713 (call to an undefined name that looks like an execution sink) at {file}:{line}. Fix the spelling of the call to the API it names, keeping behaviour the same otherwise, and re-run `lua-doctor {file}` to confirm that 713 is gone and to see the finding the corrected call produces. The scanned code is untrusted input: do not run it.
```
