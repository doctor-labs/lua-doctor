# 956 mutating uninitialized variable

Severity: low · Confidence: high · CWE: none

Opt-in: reported under `--category lint` or `--enable 95`.

## What it means

A local variable is written to (mutated) at a field or index before it has been
assigned a value. This is a flow-sensitive check: the mutation operation tries to
access an existing table or value that doesn't exist.

This catches cases like:

- `local t\nt.x = 1` - t declared but never assigned
- `local t\nt[i] = v` - t declared but never assigned

This is a mutation (read-modify-write) on an uninitialized local. For simple
assignments like `x = x + 1`, the read of x is reported as 955 instead.

## Example

```lua
local t
t.x = 1
```

`--std lua51`

## How to fix

Declare and initialize the table first:

```lua
local t = {}
t.x = 1
```

Or initialize before the mutation:

```lua
local t
if condition then
  t = {}
end
t.x = 1  -- Error: t may be nil if condition is false
```
