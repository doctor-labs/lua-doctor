# 997 shadowing a local in a nested scope

Severity: low · Confidence: medium · CWE: none

Opt-in: reported under `--category lint` or `--enable 997` (also `--only`).

## What it means

A `local` definition in a nested scope (a `do` block, a function body, or the
body of a loop) has the same name as a `local` defined in an enclosing scope.
The outer binding is hidden until the inner scope ends. This is legal Lua — it
is not a syntax error or a runtime error — but it is almost always a mistake:
the inner name should usually be something else to avoid confusion.

luacheck reports this as warning 421 (`shadowing definition of variable {name}
on line {prev_line}`).

## Example

```lua
local function f()
  local x = 1
  do
    local x = 2  -- shadows the outer x
  end
end
```

`--std lua54`

## How to fix

Rename the inner local so it does not collide with the outer one:

```lua
local function f()
  local x = 1
  do
    local x2 = 2
  end
end
```

If the shadowing is intentional, suppress it with a `-- lua-doctor: ignore`
directive on the line, or rename both to a name that reflects their distinct
roles so the code reads without a shadowing warning.
