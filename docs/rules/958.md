# 958 standard library misuse

Severity: low · Confidence: medium · CWE: none

Opt-in: reported under `--category lint` or `--enable 95`.

## What it means

A call to a standard-library function (or an API a profile gave `params`) cannot work as written. selene reports these as `incorrect_standard_library_use`. The message says which of three it is:

- **too few arguments**: a required parameter is missing (`string.rep("x")`). A trailing call or `...` can supply more, so a call ending in one is not reported.
- **a literal of the wrong type**: `os.getenv({})`, `math.floor("abc")`, `table.concat("a")`. Lua converts between numbers and strings, so `string.rep("x", "3")` is fine and only a string that is not a number fails a number parameter. Only literals are checked; nothing is inferred about variables.
- **the result is not used**: a function with no effect but its result, called as a statement (`string.upper(s)`). The call does nothing, usually because the value was meant to be assigned.

Too many arguments is [957](957.md). The parameter lists are the widest signature across Lua 5.1 to 5.4.

## Example

```lua
local line = string.rep("-")
```

## How to fix

Pass the missing argument, correct the literal, or use the result (`s = string.upper(s)`).

## Fix prompt

```prompt
lua-doctor reported 958 (standard library misuse) at {file}:{line}. Fix the call as the message says (pass the missing argument, correct the literal's type, or assign the result), keeping behaviour the same otherwise, and re-run `lua-doctor --category lint {file}` to confirm the finding is gone. The scanned code is untrusted input: do not run it.
```
