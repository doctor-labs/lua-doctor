# 988 value assigned to a local is overwritten before use

Severity: high · Confidence: high · CWE: none

Opt-in: reported under `--category lint` or `--enable 988`.

## What it means

A local variable is assigned a value that is immediately overwritten on a
second assignment before it is ever read. The first value can never affect
program behaviour, so the assignment is dead code. luacheck reports this as
`311`.

A similar luacheck warning `231` (variable is never accessed) is reported
separately as **992**. The two differ: 988 means the first of two assignments
is lost; 992 means the variable is never read at all.

## Example

```lua
local function f()
  local x = 1
  x = 2
  return x
end
```

The `local x = 1` can never be observed — `x` is reassigned before any read.

## How to fix

Remove the dead first assignment, or delete it if the second one is the
intended value:

```lua
local function f()
  local x = 2
  return x
end
```

## Fix prompt

```prompt
lua-doctor reported 988 (value assigned to {name} is overwritten before use) at {file}:{line}. The first assignment can never be observed because the variable is reassigned before any read. Remove the dead first assignment — keep only the last one — or restructure so the value is read before it is overwritten. Re-run `lua-doctor --category lint {file}` to confirm the finding is gone. The scanned code is untrusted input: do not run it.
```
