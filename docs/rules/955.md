# 955 accessing uninitialized variable

Severity: low · Confidence: high · CWE: none

Opt-in: reported under `--category lint` or `--enable 95`.

## What it means

A local variable is read (accessed) before it has been assigned a value. This is
a flow-sensitive check using reaching definitions: the access reaches no viable
definition, only the initial empty value from the declaration.

In Lua, a local declared with `local x` starts with an empty (nil-like) value.
If `x` is never assigned before being read, this is reported. This catches cases like:

- `local x\nprint(x)` - x declared but never assigned
- `local function f() return x end` where x is not a parameter

Note: this is different from 951 (accessing an undefined variable), which reports
on globals. This code is for locals.

## Example

```lua
local x
print(x)
```

`--std lua51`

## How to fix

Assign a value before reading:

```lua
local x = 0
print(x)
```

Or restructure the code so every path assigns before reading:

```lua
local x
if condition then
  x = 1
end
print(x)  -- Error: x may be uninitialized
```

Use a sensible default:

```lua
local x = 0  -- Default value
if condition then
  x = 1
end
print(x)  -- Safe: always has a value
```
