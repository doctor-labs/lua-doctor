# 965 reversed numeric for

Severity: low · Confidence: medium · CWE: none

Opt-in: reported under `--category lint` or `--enable 95`.

## What it means

A numeric `for v = A, B do` has no step argument, and A and B are both number literals with A > B (for example `for i = 10, 1 do`), or A is a length operator `#t` and B is the literal 1 (or 0) (for example `for i = #t, 1 do`). With no step the default is +1, so the loop never runs: in the numeric case the start is already past the end, and in the `#t, 1` case the author almost certainly meant to count down with `, -1`. luacheck reports this as 571 and selene as `suspicious_reverse_loop`.

Anything that is not a literal is never reported: only `for i = n, m do` (where `n` and `m` are variables) is never flagged.

## Example

```lua
for i = 10, 1 do
   process(item[i])
end
```

## How to fix

Add an explicit negative step so the loop counts down: `for i = 10, 1, -1 do`. For the `#t, 1` form, the intended fix is `for i = #t, 1, -1 do`.
