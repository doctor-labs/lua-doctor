# 952 setting or mutating a non-standard global variable

Severity: low · Confidence: medium · CWE: none

Opt-in: reported under `--category lint` or `--enable 95`.

## What it means

The code assigns a global the Lua standard and the loaded platform profiles do not define (`counter = 0`, setting) or writes a field of one (`config.debug = true`, mutating). luacheck reports these as 111 and 112. A global written this way is shared by every chunk in the process, which is how one script's state leaks into another and how a sandbox's environment is altered, so a firmware script that does this on purpose should say so.

## Example

```lua
counter = 0
```

## How to fix

Make the variable `local`, or return it from the module. If a global is intended, declare it in a profile with `globals` so it is a defined name.

## Fix prompt

```prompt
lua-doctor reported 952 (setting or mutating a non-standard global variable) at {file}:{line}. Make the variable local, or return it from the module, keeping behaviour the same otherwise, and re-run `lua-doctor --category lint {file}` to confirm the finding is gone. The scanned code is untrusted input: do not run it.
```
