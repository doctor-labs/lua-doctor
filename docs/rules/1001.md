# 1001 shadowing an upvalue argument in a nested scope

Severity: low · Confidence: medium · CWE: none

Opt-in: reported under `--category lint` or `--enable 1001` (also `--only`).

## What it means

A `local` definition in a nested function has the same name as an argument of
an enclosing function — an upvalue that is a function parameter. The outer
argument is hidden inside the nested function, which can cause subtle bugs if
the author intended to read or modify the upvalue rather than create a new
local. This is legal Lua — it is not a syntax error or a runtime error — but it
is almost always a mistake.

luacheck reports this as warning 432 (`shadowing upvalue argument {name} on line
{prev_line}`).

## Example

```lua
local function outer(a)
  local function inner()
    local a = 2  -- shadows the upvalue argument a
  end
end
```

`--std lua54`

## How to fix

Rename the inner local so it does not collide with the upvalue argument:

```lua
local function outer(a)
  local function inner()
    local b = 2
  end
end
```

If the shadowing is intentional, suppress it with a `-- lua-doctor: ignore`
directive on the line.
