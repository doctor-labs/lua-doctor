# 957 more arguments passed than the function takes

Severity: low · Confidence: medium · CWE: none

Opt-in: reported under `--category lint` or `--enable 95`.

## What it means

A call passes more arguments than the function accepts, so the extra ones are silently dropped. selene reports this as `mismatched_arg_count`. It is usually a sign the callee is not the function the author had in mind, or that an argument sits in the wrong position. For a standard-library or declared sink that matters: `os.execute(cmd, extra)` ignores `extra`, and `io.popen` takes its mode second, so a value in the wrong slot never reaches the place that executes it.

Which functions are checked:

- the Lua standard library, from a parameter list that is the widest signature across Lua 5.1 to 5.4 (a call is reported only when no version accepts it);
- an API a platform profile gives a `params` list on its sink, source, shape or propagator entry;
- a local function defined in the file, against the most generous definition that can reach the call (a function that takes `...` is never reported).

Fewer arguments than required is 958 (not yet reported).

## Example

```lua
local function add(a, b) return a + b end
local total = add(1, 2, 3)
```

## How to fix

Remove the extra arguments, or fix the function that was meant to take them. If the call is right and the declaration is wrong, correct the declaration (or the profile's `params`).
