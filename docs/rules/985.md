# 985 local redefined in the same scope

Severity: low · Confidence: medium · CWE: none

Opt-in: reported under `--category lint` or `--enable 98`.

## What it means

A `local` declaration — including `local function f()` — binds a name that is
already bound in the same scope, so the second binding shadows the first while it
is still in scope. luacheck reports this as code 411.

Lua does not forbid this: `local x = 1; local x = 2` is legal. But the first
binding is dead the moment the second appears, which is almost always a
copy-paste or rename mistake.

A binding in a **nested** scope (`do local x = 2 end`) is not a redefinition: each
scope may have its own `x`. Neither is a `local` in a sibling block.

## Example

```lua
local x = 1
local x = 2  -- 985: x was already defined in this scope
return x
```

`local function` is the same:

```lua
local function f()
  local a = 1
  local function a() end  -- 985: a was already defined as a local
  return a
end
```

Three bindings of the same name in one scope produce two findings:

```lua
local x = 1
local x = 2  -- 985
local x = 3  -- 985
```

## How to fix

Remove the duplicate declaration, or rename the variable if a new name is needed:

```lua
local x = 1
local y = 2
return x + y
```
