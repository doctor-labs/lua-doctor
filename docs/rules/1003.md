# 1003 invalid string escape

Severity: low · Confidence: high · CWE: none

Opt-in: reported under `--category lint` or `--enable 1003` (also `--only`).

## What it means

A string contains a backslash followed by a character that is not a Lua escape,
such as `"\q"` or `'\d'`. Lua 5.1 silently drops the backslash, so `"\q"` is
`q`. Lua 5.2 and later reject the whole file with "invalid escape sequence".
selene reports this as `bad_string_escape`.

The check covers the escape character only, so a valid escape (`\n`, `\t`,
`\\`, `\"`, `\65`, `\x41`, `\u{...}`, a backslash-newline) is never reported.
Comments and long strings (`[[...]]`) are not scanned: a backslash there is
literal text.

## Example

A Windows path written without doubling the backslash:

```lua
local path = "C:\dir\file"
```

`--std lua51`

## How to fix

Write the backslash as `\\`, or use a valid escape. A reported file still runs
under Lua 5.1, but it fails to parse under Lua 5.2 and later.

```lua
local path = "C:\\dir\\file"
```

## Fix prompt

```prompt
lua-doctor reported 1003 (invalid string escape) at {file}:{line}: {name} is not a Lua escape. Lua 5.1 drops the backslash and Lua 5.2+ rejects the file. Replace the backslash with a valid escape, or write it as a double backslash if a literal backslash is meant. Re-run `lua-doctor --category lint {file}` to confirm the finding is gone. The scanned code is untrusted input: do not run it.
```
