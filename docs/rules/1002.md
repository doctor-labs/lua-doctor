# 1002 shadowing an upvalue loop variable in a nested scope

Severity: low · Confidence: medium · CWE: none

Opt-in: reported under `--category lint` or `--enable 1002` (also `--only`).

## What it means

A `local` definition in a nested function has the same name as the loop variable
of an enclosing `for` loop — an upvalue that is a loop variable. The outer loop
variable is hidden inside the nested function, which can cause subtle bugs if
the author intended to read or modify the upvalue rather than create a new
local. This is legal Lua — it is not a syntax error or a runtime error — but it
is almost usually a mistake.

luacheck reports this as warning 433 (`shadowing upvalue loop variable {name} on
line {prev_line}`).

## Example

```lua
for i = 1, 3 do
  local function inner()
    local i = 2  -- shadows the upvalue loop variable i
  end
end
```

`--std lua54`

## How to fix

Rename the inner local so it does not collide with the upvalue loop variable:

```lua
for i = 1, 3 do
  local function inner()
    local j = 2
  end
end
```

If the shadowing is intentional, suppress it with a `-- lua-doctor: ignore`
directive on the line.
