# 1000 shadowing an upvalue in a nested scope

Severity: low · Confidence: medium · CWE: none

Opt-in: reported under `--category lint` or `--enable 1000` (also `--only`).

## What it means

A `local` definition in a nested function has the same name as a variable defined
in an enclosing function — an upvalue. The outer variable is hidden inside the
nested function, which can cause subtle bugs if the author intended to read or
modify the upvalue rather than create a new local. This is legal Lua — it is not
a syntax error or a runtime error — but it is almost always a mistake.

luacheck reports this as warning 431 (`shadowing upvalue {name} on line
{prev_line}`).

## Example

```lua
local function outer()
  local x = 1
  local function inner()
    local x = 2  -- shadows the upvalue x
  end
end
```

`--std lua54`

## How to fix

Rename the inner local so it does not collide with the upvalue:

```lua
local function outer()
  local x = 1
  local function inner()
    local y = 2
  end
end
```

If the shadowing is intentional, suppress it with a `-- lua-doctor: ignore`
directive on the line.

## Fix prompt

