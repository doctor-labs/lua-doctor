# 999 shadowing a loop variable in a nested scope

Severity: low · Confidence: medium · CWE: none

Opt-in: reported under `--category lint` or `--enable 999` (also `--only`).

## What it means

A `local` definition in a nested scope (a `do` block, a function body, or the
body of another loop) has the same name as the loop variable of an enclosing
`for` loop. The outer loop variable is hidden until the inner scope ends. This is
legal Lua — it is not a syntax error or a runtime error — but it is almost always
a mistake: the inner name should usually be something else.

Note: a `local` declared directly in the body of the `for` loop (without a
further `do` block) is in the same scope as the loop variable and is reported as
a same-scope redefinition (luacheck 413), not as shadowing.

luacheck reports this as warning 423 (`shadowing definition of loop variable
{name} on line {prev_line}`).

## Example

```lua
for i = 1, 3 do
  do
    local i = 10  -- shadows the loop variable i
  end
end
```

`--std lua54`

## How to fix

Rename the inner local so it does not collide with the loop variable:

```lua
for i = 1, 3 do
  do
    local j = 10
  end
end
```

If the shadowing is intentional, suppress it with a `-- lua-doctor: ignore`
directive on the line.
