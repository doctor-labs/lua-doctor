# 979 a comparison inside type()

Severity: low · Confidence: high · CWE: none

Opt-in: reported under `--category lint` or `--enable 95`.

## What it means

`type()` is called with a comparison expression (`==`, `~=`, `<`, `<=`, `>` or
`>=`) as its argument, instead of comparing `type(x)` to a string literal.
selene reports this as `type_check_inside_call`.

`type(x)` returns the type of `x` as a string. Passing a comparison —
`type(x == "string")` — does not check the type of `x`; it passes the boolean
result of the comparison to the (non-standard) `type`, which then reports
`"boolean"`. The almost-certain intent was `type(x) == "string"`, and the
finding is almost always a misplaced parenthesis.

A local function or variable named `type` shadows the global and is **not**
reported; this rule only fires when the callee `Id "type"` resolves to the
global standard library function (no `.var` field after `resolve_locals`).

## Example

The misplaced-parenthesis form, almost always a typo:

```lua
if type(x == "string") then end
local k = type(t[1] == "number")
```

`--std lua51`

## How to fix

Move the comparison outside of `type()`:

```lua
if type(x) == "string" then end
local k = type(t[1]) == "number"
```
