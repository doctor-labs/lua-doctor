# 981 module-level global assigned but never read

Severity: low · Confidence: medium · CWE: none

Opt-in: reported under `--category lint` or `--enable 95`.

## What it means

A global name is assigned at module level but never read anywhere in the file:
`function unused_helper() ... end` or `global_name = value` with no use of the
name afterwards. luacheck reports this as `131` (unused global).

A read through `_G.NAME` counts as a read of `NAME`, and an indexed access
like `name.field` counts as a read of `name`. A local with the same name is not
a global: it has its own scope and is never reported here (luacheck reports
unused locals separately as `211`).

## Example

A module-level function defined but never called:

```lua
function unused_helper()
   return 1
end
```

`--std lua51`

## How to fix

Either use the global, or remove the dead definition. If the global is meant to
be called from elsewhere, the caller is in a different file, so this rule is a
file-local reminder: the name is set here and never read here.

```lua
function helper()
   return 1
end
return helper()
```
