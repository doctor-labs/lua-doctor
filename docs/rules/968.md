# 968 this table mixes positional and keyed entries

Severity: low · Confidence: medium · CWE: none

Opt-in: reported under `--category lint` or `--enable 95`.

## What it means

A table constructor has both positional entries (no key) and keyed entries (`name
= value` or `[expr] = value`). Mixing the two styles is almost always an
accidental index: the positional entries fill the `1..n` slots, and a keyed entry
that happens to land on a later number is silently placed at its key instead.
selene reports this as `mixed_table`.

## Example

```lua
local t = {1, 2, a = 3}
```

## How to fix

Pick one style. If the keyed entry is meant to be positional, write it without a
key. If only some entries are keyed, give the positional ones explicit numeric
keys so the intent is clear.
