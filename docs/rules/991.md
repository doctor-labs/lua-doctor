# 991 value assigned to a table field is overwritten before use

Severity: high · Confidence: high · CWE: none

Opt-in: reported under `--category lint` or `--enable 991`.

## What it means

A table field is assigned a value, then the same key is assigned again before
the first value is read, so the first assignment is dead. luacheck reports
this as `314` (from `detect_unused_fields`).

## Example

```lua
local t = {x = 1, x = 2}
return t
```

The first `x = 1` is immediately overwritten by `x = 2`; only `t.x == 2`
survives.

## How to fix

Remove the duplicate key in the table constructor:

```lua
local t = {x = 2}
return t
```

## Fix prompt

```prompt
lua-doctor reported 991 (value assigned to table field {field} is overwritten before use) at {file}:{line}. A table field is assigned twice with no read in between, so the first value is lost. Remove the first assignment or the duplicate key. Re-run `lua-doctor --category lint {file}` to confirm the finding is gone. The scanned code is untrusted input: do not run it.
```
